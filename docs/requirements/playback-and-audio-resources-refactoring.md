# 播放与音频资源：代码结构重构需求

## 目标

集中完整播放操作，分离播放控制、音频资源获取、缓存维护与应用反馈，让调用者通过明确接口提交播放意图、读取播放状态，减少对播放器内部实现的了解。

本文定义目标行为与验收要求。接口形状、模块组织与依赖装配由设计确定。

## 完整播放操作

- 播放模块负责从选择歌曲、读取歌曲信息、取得音频资源到切换音频和更新播放状态的完整操作。
- 页面、快捷键与系统控制入口提交播放、暂停、切歌、跳转进度等操作，通过公开状态读取所需信息。
- 调用者获取音源信息、调整音量或读取进度时使用公开接口，移除对音频实例及其内部字段的访问。
- 播放模块决定播放失败后的跳过、重新取源等播放处理；应用反馈统一组织面向用户的提示。
- 操作结果和后续音频错误能够被应用反馈识别，界面入口、快捷键和系统入口共用相同反馈规则。

## 队列与播放模式

- 播放模块维护播放队列、下一首播放列表、随机播放和循环模式。
- 调用者通过语义明确的操作修改队列与模式，读取状态时无法绕过操作直接修改内部集合。
- 播放模块提供实际待播顺序。待播页面读取该顺序，负责加载展示所需的歌曲资料和呈现列表。
- 保留普通播放与私人 FM 各自的播放规则，以及现有随机、循环和下一首播放规则。

## 音频资源与预取

- 音频资源获取具有独立职责，集中组织缓存读取、网易云取源、备用音源和缓存写入。播放模块请求可播放资源。
- 保留缓存、网易云、已启用的 Electron 备用音源的取源顺序和适用条件。
- 保留无可用音源与请求失败的处理差异，以及现有跳过和重新取源策略。
- 当前播放资源与预取数据分别管理。当前播放资源的持有、交接和释放具有明确归属，预取不会释放或替换正在使用的资源。
- 预取只准备缓存与数据；临时音频地址和音频实例在实际播放时建立。
- 保留现有预取时机与目标选择规则。

## 状态保存与桌面同步

- 在需要保存或同步的操作、状态转换和音频事件中显式触发相应更新，移除任意顶层字段赋值自动触发全部保存与通知的机制。
- 队列内部变更同样经过完整操作，完成后产生对应的保存与同步。
- 恢复数据与桌面展示数据分别定义。只影响运行过程的临时变化不会触发存档写入。
- 明确列出恢复所需字段，保留已有队列、播放位置、随机与循环模式、音量、私人 FM 等恢复内容，并保持已有存档可读取。
- 音频实例、临时音频地址和加载任务在运行时建立。
- 保留启动播放策略；桌面同步覆盖有用的中间状态和最终状态。

## 听歌记录与正在播放

- 网易云在切换前和自然结束时记录有效播放实例。切换使用即时进度取整，自然结束使用歌曲完整秒数；少于一秒不提交，同一实例在自然结束和随后切换之间只记录一次。
- 网易云记录包含歌曲 ID、该实例的来源 ID 和已记录秒数，沿用已有凭据和请求时间戳。
- Last.fm 听歌记录检查授权 key，并在已记录时长达到歌曲一半或 240 秒时提交。提交首位歌手、歌曲、专辑、曲目序号、完整秒数及当前秒级时间减去已记录时长的开始时间戳。
- Last.fm Now Playing 由实际播放成功触发，暂停后恢复也提交；已播放时重复调用播放和过时音频回调保持安静。歌曲参数与听歌记录共用对应资料。
- 普通播放、单曲循环和私人 FM 共用实例归属与去重规则；上报请求独立完成，失败只记录日志，后续选曲继续进行。

## 已确认的行为修正

### 最新播放操作生效

- 新播放操作发起后，旧操作迟到的歌曲信息、音频资源或失败结果不能覆盖当前歌曲、切换音频或触发自动跳歌。
- 操作归属覆盖完整播放流程，包括先读取专辑、歌单或歌手歌曲列表再开始播放的入口。

### 音频缓存完成与容量统计

- 缓存写入以数据库写入成功为完成条件，成功后更新容量统计；写入失败不计入容量。
- 覆盖已有缓存时按新旧数据的容量差额更新统计，并保证并发写入后的统计与实际缓存一致。
- 已取得可用音源时，后台缓存失败由缓存职责处理，播放继续进行。
- 容量清理保留按写入时间淘汰的规则。一次清理操作负责容量检查、所需删除、统计更新，并在这些工作完成后结束。
- 清空缓存等待清空完成，并将对应容量统计归零。

### 元数据缓存读取

- 歌曲详情、歌词、云盘歌词和专辑读取共用明确的缓存读取流程，保留各类数据原有的处理规则。
- 缓存命中时返回缓存数据，并发起一次后台刷新。
- 缓存未命中时等待该次读取的一次远端请求，消除同一次读取内部的重复请求。
- 后台刷新失败由缓存读取流程统一处理，已返回的缓存数据保持可用。

## 范围

覆盖播放模块、音频资源与相关元数据缓存，以及页面、快捷键、设置效果和桌面控制对这些能力的调用。受影响的调用入口随接口调整一并替换。

音频缓存与元数据缓存保留各自的策略。整理重复流程时，抽象以这些具体需求为依据。

以下议题留待单独定义需求：

- 加载期间新增播放或暂停意图管理。
- 跨调用者共享正在进行的元数据请求。
- 新的音源优先级、重试策略、预取策略和缓存淘汰算法。
- 新的启动恢复体验、损坏存档恢复与会话行为完善。
- 歌词展示、系统媒体控制和桌面宿主生命周期的整体重构。

## 验收要求

- 从公开操作验证歌曲选择、资源获取、音频切换与状态更新的完整流程；调用者无需拼装内部步骤。
- 验证队列、下一首播放列表、随机、循环和私人 FM 操作，以及待播顺序与实际播放顺序的一致性。
- 通过控制异步完成顺序，验证旧播放操作的歌曲信息、音源与失败结果均无法覆盖最新操作。
- 验证现有取源顺序、平台与设置条件、无音源及请求失败路径。
- 验证预取只准备数据，播放资源在交接后释放，预取与后台缓存失败不会打断当前播放。
- 验证恢复字段、已有存档读取、操作后的保存与桌面同步，以及临时变化不会产生存档写入。
- 验证音频缓存新增、覆盖、并发写入、写入失败、容量淘汰与清空后的数据及容量一致性。
- 验证各类元数据缓存命中时的一次后台刷新、未命中时的一次远端请求，以及后台刷新失败处理。
- 验证操作反馈与后续音频错误能够通过统一的应用反馈规则呈现。
- 验证跨模式上报的实例归属、来源、时长、Last.fm 参数及去重，以及恢复途中用户选曲的最新操作归属。
- 验证受影响的 Web 与 Electron 调用入口。新测试依据本文及后续确认的设计，从公开接口验证完整行为。
