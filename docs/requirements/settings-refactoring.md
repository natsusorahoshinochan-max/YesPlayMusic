# 设置操作与持久化：代码结构重构需求

## 状态与目标

本文定义已确认、待实现的结构重构需求。

集中设置变更的完整流程，让调用者通过明确的 interface 完成保存与实际应用，降低修改设置时需要了解的内部细节。

## 当前结构

preferences 已持有设置与音乐库筛选偏好，应用启动已有显式装配，持久化具有统一写入位置。设置页仍分别组织状态更新、主题应用、语言切换、播放器调用和 Electron IPC；启动恢复与运行时修改分别掌握部分设置应用规则。

持久化按 preferences、session、library 的 mutation 触发，内存集合和登录过程展示状态变化也会写回设置与身份数据。

## 完整设置操作

- 保存设置与应用其效果由完整操作协调。调用者提交修改后，无需另行调用主题函数、播放器或发送 IPC。
- 页面负责输入、展示与按键捕获。尚未提交的编辑内容由页面持有，保留已有提交时机。
- 平台差异通过实际的 Web、Electron adapter 表达；业务调用者无需了解 IPC 通道。
- 纯数据偏好可以共用修改入口；具有执行流程的设置封装对应完整操作。interface 的具体组织由设计确定。

## 恢复与规则归属

- 默认值、已有迁移和取值转换集中管理，页面读取可用配置，不在各处重复补默认值。
- 启动恢复与运行时修改共用如何应用配置的规则。
- 启动负责应用恢复的配置；修改音质时清理缓存等由变更触发的动作，只在对应修改时执行。
- 快捷键录制期间的暂停、保存与恢复平台操作归入设置流程。页面负责按键输入与录制状态展示。

## 持久化

- 保留现有存储格式与数据归属。
- 仅在需要持久化的数据发生变化时写回对应存储；修改主题只保存设置，身份字段变化只写回相关身份数据。
- 收藏集合加载、二维码展示状态等内存变化不触发设置或身份数据写回。
- 保留动态设置、未知存储字段和已有本地数据的读写能力。

## 范围

覆盖设置入口、preferences、默认值与已有迁移、持久化订阅、启动恢复，以及设置变更所调用的浏览器、播放器和 Electron 应用效果。

播放器与缓存算法的整体重构、损坏存档恢复、新的校验机制和新的错误体验属于独立议题。

## 验收要求

- 修改设置的调用者通过完整操作完成提交，无需拼装保存与应用步骤。
- 相同配置在启动恢复与运行时修改中使用共同的应用规则。
- 设置变更与持久化写回的对应关系可通过公开操作和存储 adapter 验证；无关内存变化不产生写回。
- 默认值、已有迁移和取值转换具有明确归属，页面重复规则已消除。
- 快捷键录制的平台控制通过明确 interface 调用，页面不直接组织相应 IPC。
- 受影响的 Web、Electron 设置功能及本地数据保持可用。
- 新测试依据本文及后续确认的设计编写，从公开 interface 验证完整流程。
