# 会话与请求结果：代码结构重构需求

## 目标

整理 YesPlayMusic 的会话与请求处理代码，集中分散的规则，简化调用接口，理顺依赖，消除重复实现和流程编排，降低理解、修改与验证成本。

架构分析以整个项目的 understand-anything graph 和源码为依据，覆盖完整调用链，包括页面、路由、Vuex、请求工具、持久化和运行环境之间的关系。

## 范围

覆盖现有登录、身份恢复、身份切换、退出、会话检查、请求结果处理，以及相关的账号数据加载编排。

一次性替换相关内部接口和全部调用者，删除旧鉴权接口、重复实现及新旧接口转接层。播放器、搜索、公共详情页和桌面功能完成受接口替换影响的调用适配。

## 职责整理

| 职责边界 | 整理要求 |
| --- | --- |
| 会话 | 集中现有认证、凭据、身份判断、恢复、切换和退出规则。 |
| 请求 | 集中传输与请求结果处理，将退出、导航和提示交给对应的业务与应用协调代码。 |
| 应用协调 | 收拢现有会话操作与账号数据、路由、提示之间的流程编排。 |
| 账号数据 | 由对应模块持有资料和音乐库数据，集中现有加载逻辑及数据间的依赖关系。 |
| 环境适配 | 封装 Web、Electron 实际存在的凭据存取、认证调用和身份恢复差异。 |

模块边界应封装实际复杂度并减少调用者需要了解的细节。按现有职责和依赖组织实现，避免为每项职责机械建立独立模块。

会话核心规则通过明确的依赖接口使用存储和认证服务。路由跳转、提示展示和全局状态协调放在应用边界，消除会话、请求、router 与 store 之间的循环依赖。

## 接口与调用者

- 将恢复身份、登录、选择公开音乐库浏览身份、退出等现有流程封装成完整操作。
- 集中身份与权限判断，页面和路由通过统一接口读取，删除各处自行组合 cookie、登录模式和用户资料的重复判断。
- 会话状态由会话操作统一维护，调用者通过查询接口读取。
- 将凭据处理、存储访问和流程执行顺序封装在内部，减少调用者对内部结构的了解。
- 将请求中的会话失效处理与应用副作用分离，保持调用链清晰。
- 修改接口时同步调整全部调用者，移除失去用途的辅助函数和重复分支。

## 数据加载与持久化

- 收拢 App、页面和 Vuex 中重复的资料与音乐库加载编排。
- 明确现有数据加载依赖，例如喜欢的歌单标识与歌曲详情之间的依赖，集中表达执行顺序。
- 按数据归属整理身份数据和用户偏好的访问代码，避免调用者操作整个混合存储对象。
- 将本地读取、启动迁移、持久化写回和初始化顺序纳入调用链分析，保持它们对数据结构的理解一致。
- 优先沿用现有存储格式；结构调整确实涉及格式变化时，提供对应迁移并验证读取、转换和后续写回。

## 兼容约束

- 保留 Vue 2、Vuex、Axios 技术栈，以及 Web、Electron 两种运行方式。
- 保持访客、用户名公开音乐库浏览和网易云账号登录的现有功能含义，保留 Last.fm 授权的独立性。
- 保留已有设置，包括动态添加的字段，以及身份资料、凭据、播放队列、播放进度和缓存的读取能力。
- 通过现有登录、恢复、退出、请求成功与失败路径核对外部行为，保持结构替换前后的功能连续性。

会话状态、并发控制和请求失败契约的行为改进见[会话行为完善需求](session-behavior-improvements.md)。结构重构的交付以本文件的职责、接口和兼容要求为准。

## 验收要求

- 会话规则具有明确归属，页面、路由和其他调用者使用统一接口。
- 请求层中的退出、导航和提示副作用已移至对应的业务或应用协调位置。
- 相关循环依赖、重复鉴权判断和重复流程编排得到消除。
- 全部相关调用者完成接口替换，旧鉴权接口和转接层已删除。
- 外围改动直接对应接口替换或依赖整理。
- 通过公开接口验证已有完整流程，测试不绑定内部函数拆分。
- Web 与 Electron 的登录、恢复、退出和受影响请求链路保持可用。
- 涉及持久化的改动通过存储样本验证，已有数据能继续读取和正确写回。
