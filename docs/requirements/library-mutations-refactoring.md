# 音乐库变更与歌单详情：代码结构重构需求

## 状态与目标

本文定义已确认、待实现的结构重构需求。

整理音乐库变更的结果表达、执行权限与歌单详情更新协作，让调用者通过明确的 interface 完成操作，消除远端协议知识和父页面内部方法的泄漏。

## 当前结构

library 已集中收藏、创建歌单、删除、增删曲目等远端写操作，并维护相关音乐库集合。创建歌单并添加歌曲已由一个操作组织。

页面、弹窗与列表仍分别检查 code、body.code 等响应字段。TrackList 删除歌曲后调用父页面的 removeTrack 方法，父页面再修改自己的歌单详情。页面和 library 重复进行执行前的账号权限检查。

## 变更结果

- library 统一解释远端响应，向调用者返回明确的操作结果。页面无需理解远端响应字段和嵌套结构。
- 创建歌单并添加歌曲沿用已有完整操作，明确表达创建结果与添加结果；调用者无需理解两次请求的响应格式。
- 结果能够表达创建成功但添加失败的情况。自动重试与补偿删除属于独立行为需求。
- 页面负责确认框、提示和展示；远端协议解释与业务结果判断归入 library。

## 权限归属

- library 统一检查操作是否具备所需的网易云账号会话权限。
- 页面根据身份控制入口展示，移除重复的执行前权限检查。
- 页面与普通 JavaScript 调用者使用同一套操作和权限规则。
- 保持访客、公开音乐库浏览身份与网易云账号会话的功能含义。

## 歌单详情更新

- 明确音乐库集合与当前歌单详情各自的维护职责。
- 变更成功后的歌单详情更新通过明确 interface 协作，移除对父页面内部方法和页面层次的依赖。
- 整理远端变更、结果解释与详情更新的完整调用链；接口替换同时消除重复业务编排。
- 歌单详情由页面还是独立 module 维护，在设计中比较确定。

## 范围

覆盖 library 写操作，以及列表、歌单详情、收藏入口和相关弹窗对操作结果、权限及数据更新的使用。

会话隔离、账号切换后的全局刷新、统一请求失败语义、自动重试与新的失败恢复体验属于独立行为需求。

## 验收要求

- 调用者通过明确的业务结果组织展示，不再读取远端响应中的 code、body.code 等协议字段。
- 创建并加曲的调用者可以区分创建与添加的结果，无需了解内部请求编排。
- 执行权限具有单一归属，页面重复检查已消除，所有变更入口共用相同规则。
- 歌单详情的维护者和更新 interface 明确，列表不再调用父页面内部方法。
- 变更、集合更新、详情更新与页面展示之间的完整协作可从公开 interface 验证。
- 受影响的收藏、歌单创建、删除和曲目增删功能保持可用。
- 新测试依据本文及后续确认的设计编写；具体 interface 与结果形状由设计确定。
