# Domain docs

## Layout

This repo uses a single-context layout:

- GLOSSARY.md at the repo root
- docs/adr/ for architectural decisions

## Before exploring

Read GLOSSARY.md and any ADRs relevant to the area being explored.

If a document or directory is absent, proceed silently. Domain modeling
creates documentation when terminology or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
Respect explicitly avoided synonyms.

When a needed concept is missing, reconsider the terminology or note the
gap for domain modeling.

## Decisions

Explicitly identify any proposal that contradicts an existing ADR,
including the ADR reference and the reason to reconsider it.
